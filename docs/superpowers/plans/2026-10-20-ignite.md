# ignite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public chezmoi repo with one-line bootstraps that turn a blank company laptop (macOS, Windows with PowerShell + WSL, or Ubuntu) into the owner's platform-engineering workstation. The repo installs one tool per job and works with or without admin rights.

**Architecture:** Thin bootstrap scripts (`bootstrap.sh` and `bootstrap.ps1`) install the prerequisites, chezmoi and mise, then run `chezmoi init --apply`. A single catalog (`home/.chezmoidata/packages.yaml`) is validated and resolved by chezmoi templates into a per-machine selection (`selected.json`). Per-OS install scripts, the shell configs and `ignite-doctor` are all rendered from that one selection. Install failures are written to a report file instead of aborting the run. `ignite-doctor` reads that report and prints the final checklist.

**Tech Stack:** chezmoi (Go templates and sprig), mise (aqua/npm/pipx backends), Homebrew, winget, Scoop, apt, bash 3.2-compatible shell, PowerShell 5.1 (bootstrap only) and 7, bats-core, Pester 5, shellcheck, PSScriptAnalyzer, gitleaks, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-20-ignite-design.md`

## Global Constraints

- Repo: public `github.com/henrypham67/ignite`, branch `main`. Commits use repo-local `user.name "Henry Pham"` and `user.email 43398131+henrypham67@users.noreply.github.com`.
- No committed file may contain a secret, token, private key, employer name, company domain or internal hostname. Employer-specific values live only in `~/.config/chezmoi/chezmoi.toml` or `~/.config/ignite/`. Test fixtures use `example.com`.
- The denylist of employer terms is **never committed**. It comes from `~/.config/ignite/denylist.txt` locally and from the `IGNITE_DENYLIST` Actions secret in CI. Matches are printed as `file:line` only, never the line content.
- `bootstrap.sh` runs under macOS `/bin/bash` 3.2: no associative arrays, `mapfile`, `${x,,}` or `declare -n`. Expanding an empty array under `set -u` needs `${arr[@]+"${arr[@]}"}`.
- `bootstrap.ps1` runs under Windows PowerShell 5.1: no `??`, ternary, `&&`/`||` pipeline chains, or `-Parallel`. Everything chezmoi runs on Windows uses `pwsh` 7.
- Templates read the OS from `.ignite.os` (`darwin|windows|linux|wsl`), never from `.chezmoi.os`. Only `.chezmoi.toml.tmpl` computes it. This keeps every template renderable for every OS in tests.
- Add/update only: no script uninstalls anything.
- No install failure aborts a run. Install scripts record failures in the report and always exit 0. Only bootstrap preconditions (bad `IGNITE_CA_CERT`, chezmoi itself failing to install) exit non-zero.
- The bootstrap never passes `--force` to chezmoi. Locally modified files must prompt.
- Admin-requiring install scripts are numbered `10`–`19` so they run first. Per-user scripts are numbered `20` and up.
- Linux means Ubuntu/Debian only.
- Stage explicit paths. Never `git add -A`. Use the `commit` skill for every commit.

## Review Focus

1. **Blank laptop with no GitHub token:** resolving `latest` through mise can hit GitHub's unauthenticated API limit (60/hour). The run must finish, every affected tool must show in the report with the hint `set GITHUB_TOKEN and retry`, and `ignite-doctor` must print the retry command. Test: Task 5, `lib.sh: rate-limit failure adds GITHUB_TOKEN hint`.
2. **Re-running after a managed file was edited locally** (for example VS Code rewriting `settings.json`): chezmoi must ask, not overwrite. Test: Task 6, `bootstrap.sh: chezmoi args never contain --force`.
3. **Secrets file values containing spaces, quotes or `$`:** a re-run must keep every existing line byte-for-byte and only append names that are missing. Test: Task 12, `secrets: existing values survive re-run byte-identical`.
4. **OneDrive-redirected Documents on Windows:** the profile shim must write to the real `$PROFILE.CurrentUserAllHosts` path, creating missing parent directories, and must not duplicate its line on re-run. Test: Task 11, `Install-IgniteProfileShim writes once under a redirected path`.
5. **`IGNITE_CA_CERT` given as a relative or `~` path, or a missing file:** the bootstrap resolves it to an absolute path, or fails with `IGNITE_CA_CERT not found: <path>` before any download. Test: Task 6, `bootstrap.sh: CA path resolution`.

## Reference (shared interfaces)

### Machine data: `[data.ignite]` in the chezmoi config

| Key | Type | Source |
|---|---|---|
| `os` | `darwin\|windows\|linux\|wsl` | computed inline in `.chezmoi.toml.tmpl`: `wsl` when `.chezmoi.os == "linux"` and `.chezmoi.kernel.osrelease \| lower \| contains "microsoft"` (the chezmoi docs' idiom) |
| `admin` | bool | env `IGNITE_ADMIN` (`1`/`0`) wins, else the existing value, else `false` |
| `email` | string | prompt `Work email for git` |
| `git_host` | `github\|gitlab` | prompt `Company git host` |
| `gitlab_url` | string | prompt `Company GitLab URL`, asked only when `git_host == gitlab`, else `""` |
| `cloud_aws`, `cloud_azure`, `cloud_gcp` | bool | prompts `Use AWS`, `Use Azure`, `Use GCP` |
| `docker_licensed` | bool | prompt `Company licenses Docker Desktop` (darwin and windows only, else `false`) |
| `group_specialist`, `group_personal` | bool | prompts `Install specialist tools`, `Install personal apps` |
| `choices` | table job→option | only jobs the owner customised, via prompt `Change default tool choices` then `Choice for <job>` per job |
| `ca_cert`, `ca_bundle` | string paths | env `IGNITE_CA_CERT_INSTALLED` / `IGNITE_CA_BUNDLE` from the bootstrap, else the existing value, else `""` |

All prompts use `prompt*Once` (`promptStringOnce . "ignite.<key>" "<prompt text>" [default]`, and the same for Bool, plus `promptChoiceOnce … <choices> [default]`). The keys for chezmoi's `--promptString/--promptBool/--promptChoice` overrides are the **prompt text**, so prompt texts must never contain `=` or `,`.

On Windows the config template also writes `[interpreters.ps1] command = "pwsh"`, `args = ["-NoLogo", "-NoProfile", "-File"]`. Config args replace chezmoi's default `-NoLogo -File`, so `-File` must be listed. Confirm on Windows CI that chezmoi appends the script path after these args.

Templates in `.chezmoitemplates` aren't loaded while the config file template runs, so `.chezmoi.toml.tmpl` must not call `template`/`includeTemplate`.

### Catalog: `home/.chezmoidata/packages.yaml`

The top key is `packages:`, a map of entry name to fields:

| Field | Meaning |
|---|---|
| `job` | required, snake_case. Duplicates are prevented per job. |
| `group` | one of `core, cloud-aws, cloud-azure, cloud-gcp, gitlab, specialist, personal`. Exactly one of `group`/`option` is set. |
| `option` | entry is selected iff the effective choice for `job` equals this value |
| `platforms` | subset of `[darwin, windows, linux, wsl]`, default all four |
| `requires` | name of another entry. Selected only if that entry is selected. |
| `admin_only` | resolves to `needs_it` when `admin` is false |
| `bin` | command `ignite-doctor` looks for. Default is the entry name; `false` disables the check. |
| `check_path` | map os→path relative to home, used instead of `bin`. On darwin, `Applications/X.app` also matches `/Applications/X.app`. |
| `completion` | `cobra` (`<bin> completion <shell>`) or `complete-c` (`complete -C <bin> <bin>`) |
| `version` | mise version, default `latest` |
| Package sources | `mise`, `mise_skip` (list of platforms), `brew`, `cask`, `user_app` (darwin URL to a .zip or .dmg), `winget`, `winget_user` (bool: has a per-user installer), `scoop`, `apt`, `script` (bool: `.chezmoitemplates/install/<name>.sh` and/or `.ps1`), `bootstrap` (bool: installed by bootstrap, only checked) |
| Other kinds (one per entry) | `krew: <plugin>`, `vscode_ext: <id>`, `archive: {url, dest, zsh_plugin: bool}` |

`home/.chezmoidata/choices.yaml` has the top key `choice_defaults:`, mapping job to an option string, or to a map os→option (`wsl` falls back to `linux`). `none` means nothing is installed for that job. `container_engine` is not listed there because it's computed: darwin → `docker-desktop` if `docker_licensed`, else `colima`; windows → `docker-desktop`, else `rancher-desktop`; linux → `docker-engine`; wsl → `none`.

### Validator rules (template `validate-catalog`)

It collects every violation and then calls `fail` once with `ignite catalog invalid:` followed by one `- <entry>: <problem>` line per violation.

- V1 `job` is present and matches `^[a-z0-9_]+$`.
- V2 exactly one of `group`/`option` is set, and `group` is in the allowed set.
- V3 `platforms` only uses known values.
- V4 exactly one kind: package sources, `krew`, `vscode_ext`, or `archive`.
- V5 each package entry has a usable source on every one of its platforms. darwin: `mise` (unless skipped), `brew`, `cask`, `user_app`, `script`, `bootstrap`. windows: `mise`, `winget`, `scoop`, `script`, `bootstrap`. linux/wsl: `mise`, `apt`, `script`, `bootstrap`.
- V6 no two entries without `option` share a `job` on a common platform.
- V7 within a job, either every entry has `option` or none does.
- V8 every optioned job other than `container_engine` has a `choice_defaults` entry, and each default value is one of that job's options or `none`.
- V9 `requires` names an existing entry that has no `requires` of its own.

### Selection (template `selected.json`)

It renders a JSON object: entry name → the entry's fields plus `"method"`. It runs `validate-catalog` first, then works out the effective choices (template `effective-choices.json`: config `choices` override `choice_defaults`, plus the computed `container_engine`). It then keeps the entries that pass all of these:
- the platform matches
- for an `option` entry, the option equals the effective choice
- for a `group` entry, the group is on (`core` is always on; `gitlab` is on when `git_host == gitlab`; the cloud and opt-in groups follow their flags)
- `requires` is satisfied

For each kept entry, `method` is the first match below:

| Platform | Order |
|---|---|
| any | `bootstrap` → `bootstrap`; `krew`/`vscode_ext`/`archive` → same name; `admin_only` and not admin → `needs_it` |
| darwin | `mise` → `brew` (admin) → `cask` (admin) → `user_app` (not admin) → `script` → `needs_it` |
| windows | `mise` → `winget` (admin) → `winget_user` (not admin and `winget_user`) → `scoop` → `script` → `needs_it` |
| linux, wsl | `mise` → `apt` (admin) → `script` → `needs_it` |

### Report file

- Path: `${XDG_STATE_HOME:-$HOME/.local/state}/ignite/report.tsv`, or `$env:LOCALAPPDATA\ignite\report.tsv` on Windows.
- Columns: `source<TAB>status<TAB>item<TAB>detail`, where status is `failed|needs-it|skipped`. Only non-ok rows are written.
- Each script starts by removing its own `source` rows, so retries clear stale failures.
- `IGNITE_SKIP` (comma-separated entry names) makes `ig_try`/`Invoke-IgniteTry` record `skipped` instead of running.
- Retry command printed by doctor: for each failed source, `chezmoi state delete --bucket=entryState --key='<home>/.chezmoiscripts/<script>.<sh|ps1>'`, then `chezmoi apply` (source → script map in `.chezmoitemplates/retry-scripts.json`). *Corrected after the final review: deleting the `scriptState` bucket does not re-run `run_onchange_` scripts, and deleting the whole `entryState` bucket also drops chezmoi's protection of locally edited files.*

### Fixed paths

- Company CA: `~/.config/ignite/ca.pem`. Bundle (system roots + company CA): `~/.config/ignite/ca-bundle.pem`.
- Secrets: `~/.config/ignite/secrets.env`, or `~/.config/ignite/secrets.ps1` on Windows.
- Doctor: `~/.local/bin/ignite-doctor`, or `~/.local/bin/ignite-doctor.ps1` on Windows.
- PowerShell profile: `~/.config/powershell/profile.ps1`. mise activation in it is `(&mise activate pwsh) | Out-String | Invoke-Expression`.
- Completions cache: `~/.cache/ignite/completions/`.
- Git identity for the ignite repo: `~/.config/git/ignite-identity`.
- On Windows the bootstrap sets user env `XDG_CONFIG_HOME=%USERPROFILE%\.config`, so Neovim, mise and Starship read `~/.config` on all three systems.
